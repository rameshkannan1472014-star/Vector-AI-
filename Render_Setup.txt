Engineer AI provider setup for Render

Upload index.html, server.py, and requirements.txt to the same GitHub service directory. Render installs dependencies with: pip install -r requirements.txt

Set these credentials in Render Environment, never in index.html or GitHub:

Gemini (chat and video; configure up to four distinct project keys if you have them):
GEMINI_API_KEY
GEMINI_API_KEY_2
GEMINI_API_KEY_3
GEMINI_API_KEY_4

Groq (automatic fallback for coding prompts when Gemini fails):
GROQ_API_KEY
GROQ_MODEL (optional; defaults to openai/gpt-oss-120b)

Cloudflare Workers AI (automatic image fallback after any Gemini image-generation failure):
CLOUDFLARE_ACCOUNT_ID
CLOUDFLARE_API_TOKEN (token must have Workers AI inference permission)
CLOUDFLARE_IMAGE_MODEL (optional; defaults to @cf/black-forest-labs/flux-1-schnell)
CLOUDFLARE_IMAGE_STEPS (optional; defaults to 4, maximum 8)

Photos: Gemini is tried first, then Cloudflare. If no Gemini keys are present, image requests go directly to Cloudflare. The chat image-creation request uses the same endpoint.

Videos: video generation requires Gemini access and quota. The default model is veo-3.1-fast-generate-preview. If GEMINI_VIDEO_MODEL is already set in Render, update it to that model or remove the override to use the default. Groq and Cloudflare image generation do not provide video fallback.

If you use a Cloudflare Global API Key instead of an API Token, configure CLOUDFLARE_API_KEY, CLOUDFLARE_EMAIL, and CLOUDFLARE_ACCOUNT_ID.

Each provider has independent access, quota, rate limits, and billing. Failover does not remove provider limits. After editing Render variables, redeploy the service and check /api/health for provider configuration status. Never share screenshots that reveal API keys; rotate any key that was exposed.
